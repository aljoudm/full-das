# Single versus dual verification on the final model (Stage 6 comparison re-run; SIMULATED)

* **Model:** final siting design: 6 interrogators at the six sites of `report/final/tables/siting_sites_medium.csv`, d* = 14.75 km, unified Pd(d) model, allocation files `results/alloc_<scenario>_22_siting.mat` (final drone layout, C_total 13,014,986 SAR), parameters of `report/final/parameters_final.md`. Same rules as Stage 9: vehicle near a road or checkpoint is routed with low priority to the site (30 m / 100 m), camera first, otherwise the nearest ready drone, patrol only after confirmation.
* **Options:** A = single check (base); B = dual everywhere; C = dual in Neutral and Cold, single in Hot.
* **Run:** 394 days per case, seed 9090, 10,004 real intruder events, common random numbers across the options (the same events, detections and classifications in A, B and C). 9 cases (3 scenarios x 3 options) in 1,407 s. Script `scripts/stage6_dual_siting.m`; data `results/stage6_dual_siting.csv`, `results/stage6_dual_siting/run_<scenario>_<option>.mat`.
* **Check:** option A reproduces `results/stage9_siting_final` (the final Stage 9 run) with a largest relative difference of 2.1e-15 (assert < 1e-9 passed, unchanged). The first attempt failed this check because it used the earlier drone layout.
* **Allocation files actually loaded (log lines of the run):** `get_allocation: loaded ...esultslloc_low_22.mat`, `alloc_medium_22.mat`, `alloc_high_22.mat` are the existing assets (cameras, interdiction points) that `run_scenario` reads through `get_allocation`; `run_scenario` then replaces the interrogators and the drone stations by `results/alloc_<scenario>_22_siting.mat` (`P.sim.siting = true`, no log line). The proof that the siting file is the one used is the match of option A with the Stage 9 final run.

**Conclusion for the medium scenario: it still holds.** Dual verification everywhere (B) lowers the false patrols from 0.227 to 0.195 per km per day (14 % less; the 95 % intervals do not overlap, but the value stays about 20 times the target FAR_km = 0.01), while the share of true alarms that reach a patrol falls from 88.5 % to 60.4 % (28 points), the median verification time rises from 490 s to 1,252 s and intruders not verified within T_resp rise from 61 % to 87 %. Option C (dual only in Neutral and Cold) lowers the false patrols as much as B (0.195) with a smaller loss (69.5 % patrol reached) but still 19 points below A. The base stays the single check. The reduction in false patrols is a little larger than in the earlier run (0 to 13 %) because the final model has more detections; the wording "barely reduces" should read "reduces by about 14 %". Low and high show the same pattern (patrol reached A -> B: low 66.4 -> 38.1 %, high 89.5 -> 78.9 %).

Definitions: false patrols = false alarms that reach a patrol after verification; patrol reached = true alarms (detected and classified as a threat) that get a patrol; not verified within T_resp = real intruders without an asset on scene within T_resp = 300 s of the alarm (includes DAS misses and classifier non-alarms); verified late = true alarms with an asset whose verification took longer than T_resp. Intervals: bootstrap over days (2,000 resamples).
